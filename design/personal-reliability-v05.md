## 1. 本轮范围

保留“洗车 / 药剂 / 记录”三个主导航，设置仍为右上角入口。保留银色 2024 乐道 L60、白色内饰、星芒风格轮毂、左前 45°车辆示意，以及洗后自动随机彩蛋、桌面组件布局预览。没有增加账号、商家、社交、订阅或彩蛋开关。

本轮可运行交付仍为 React 浏览器 Demo。iPhone 16 Pro Max 采用 440×956 逻辑布局，Apple Watch Series 10 46mm 采用 208×248。Figma 为可编辑设计与状态跳转，不能当作系统安装包或真实设备连接结果。

## 2. 已实现的规则

| 模块 | 用户怎么使用 | 数据与异常规则 |
| --- | --- | --- |
| 车辆关联 | 编排页面选择车辆，或添加另一辆车 | 使用独立车辆 ID；选择洗车预设不会切换车辆。其他车辆未配置模型时显示占位。旧资料按原车辆名称建立关联，保留原记录。暂不实现复杂车辆材质档案。 |
| 同车提醒 | 原记录填写注意事项；下次编排或核对准备清单时看到提醒 | 只展示同车未处理事项。标记“已处理”后不重复提醒；“下次再提醒”只在本轮暂缓，本轮完成后恢复。原文保留在记录中；修改原文重新进入待处理状态。 |
| 库存可信度 | 在购入标签编辑页选择已核对、估算或未知 | 旧数字默认迁移为估算，不改写余量。估算显示“约”；未知使用空余量，不画液位，不当作零。准备时若选中未知或不足的药剂则阻止扣减。只有实际取用的瓶子转为估算。 |
| 洗车方式 | 内置方案选择后编辑、另存；个人方案可更新 | 内置参考原稿不可覆盖。个人方案有修订序号；准备时冻结本次步骤、药剂用法、pH、工具和用量。已备流程不可被新方案覆盖。 |
| 历史快照 | 在洗车记录点击当时使用的药剂 | 打开只读的当时快照，不跳转为当前药剂资料。现在编辑使用方法或 pH 不会改写历史；记录的注意事项仍可编辑。 |
| 手表准备 | 手机确认取用后，在现场页“模拟接收至手表”，再从表盘开始 | 分开显示准备清单已保存、模拟副本待核验、离线演示就绪。检查本次方案版本和内容摘要，确认前不能开始。失败可重新核验，重试与步骤确认均不重复扣库存。摘要只用于演示完整性检查，不是安全签名。 |
| 备份恢复 | 设置导出完整 JSON；选文件、看数量预览，再确认替换 | 含车辆、库存、购买信息、使用履历、方案、记录和备注；不合并。校验格式、版本、mL 单位、重复 ID、余量、快照和关联。失败不更新主资料；写入成功后才切换应用状态。进行中的流程禁止恢复，可继续导出。 |
| 健康表达 | 记录与设置展示“同期活动能量”与平均心率的未连接状态 | 不产生模拟热量或心率。原生第一阶段优先考虑事后授权读取洗车时段已有样本，不能把同期所有活动归因为精确洗车消耗。 |

### 库存与时间不变量

1. 保存、编辑、选择方案不扣库存。
2. 确认已经取用时，按同瓶汇总量扣一次，记录为“流程备液”。这不是精确喷洒时间。
3. 接收核验、重试、刷新、确认步骤和结束记录均不再次扣减。
4. 到现场明确开始后才计时；路程与等待不计入。开始后的总时长含暂停，有效用时排除暂停。
5. 暂停流程不代表化学反应停止。现有 Demo 没有新增未经产品说明确认的化学停留倒计时。

### 备份边界

使用 `WashMyCarBackup` 格式、schemaVersion 1、appVersion 5、volumeUnit mL。支持校验并迁移兼容的 v2—v5 数据；未来版本、附件包或不兼容单位拒绝恢复。最大文件 12 MB。部分填写的方案草稿可以备份，但仍须通过准备检查才能执行。

备份包含用户手写地点和备注，默认不包含照片及健康明细。恢复前保留一份本机回退副本，主资料以单次存储写入替换；校验或存储写入失败时保持原主资料。本机回退副本同样依赖浏览器存储，不能代替用户下载的备份。

保留原 `washmycar-demo-v2` 存储键，避免升级创建一个空数据库。迁移不重新灌入种子药剂，不清空库存、购买资料、取用履历和洗车记录。浏览器文件来源和开发服务来源各自拥有存储，不能据此声称跨端同步。

## 4. 健康与 Apple 原生交付

当前没有接入 HealthKit、WatchConnectivity、WidgetKit、实体按钮或系统触感。网页玻璃效果也不等于 iOS 27 系统材质已验收。

原生健康优先路线：在用户明确授权后，以记录的开始/结束时间查询已有活动能量和心率样本。展示时间区间、来源、覆盖情况和缺口；缺失不补零，不根据洗车分钟数推断能量，不叠加不同层级的重复汇总。显示“同期活动能量”，因为同一时段可能含步行、休息或其他活动。是否能获得足够样本，需要真实设备验证。

Apple 文档支持按数据类型授权与查询：[HealthKit 授权](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)、[读取健康数据](https://developer.apple.com/documentation/healthkit/reading-data-from-healthkit)。事后读取优先、默认不写运动记录及“同期”口径是本项目选择。实时运动会话只作为后续评估项，参见 [Running workout sessions](https://developer.apple.com/documentation/healthkit/running-workout-sessions)。

Action button 仍规划为用户配置的准备/继续入口；Camera Control 用于真实拍摄场景；触感、系统通知、减少透明度与 Dynamic Type 需要原生验收。桌面组件保留“距上次洗车多久 / 药剂库”需求，不因参考文档遗漏而删除。
